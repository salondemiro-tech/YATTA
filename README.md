# 清掃管理システム YATTA セットアップ手順

## 1. Firebase の準備
1. Firebaseで新しいプロジェクトを作成（TORITAとは別プロジェクト推奨）
2. Authentication → Sign-in method → 「メール/パスワード」を有効化
   - 「ユーザーアクション」の「作成（登録）を有効にする」は **オンのまま** にする（アプリの社員登録で使うため）。
     勝手に作られたアカウントは、Firestore のルールで一切アクセスできない。
3. Authentication → 設定 → 承認済みドメインに GitHub Pages のドメイン（例: salondemiro-tech.github.io）を追加
4. Firestore Database を作成（ロケーション: asia-northeast1 東京）
5. Firestore → ルール に firestore.rules の内容を貼り付けて公開
6. Firestore → TTL で次の3つのポリシーを作成（設定しなくてもアプリは動きます）
   - コレクショングループ「floors」、フィールド「expireAt」（清掃データ：対象日から32日後に削除）
   - コレクショングループ「specials」、フィールド「expireAt」（完了済みの特別対応だけが対象。未完了は消えません）
   - コレクショングループ「logs」、フィールド「expireAt」（操作履歴：90日後に削除 ※仮）
7. プロジェクトの設定 → ウェブアプリを追加 → 表示された firebaseConfig を index.html の PASTE_HERE 部分に貼り付け
8. index.html を GitHub リポジトリにアップロードし、GitHub Pages で公開

## 2. 最初の管理者を登録（最初の1人だけ、コンソールで手作業）
1. Authentication → ユーザー → 「ユーザーを追加」
   - メールアドレス：`{社員番号}@yatta.local`（例：社員番号 1001 なら `1001@yatta.local`）
   - パスワード：6文字以上
2. 作成されたユーザーの「ユーザー UID」をコピー
3. Firestore → 「コレクションを開始」→ コレクションID `users` → ドキュメントID に 2 でコピーした UID を貼り付け
4. 次のフィールドを追加
   | フィールド | 型 | 値 |
   |---|---|---|
   | empNo | string | 社員番号（例：1001） |
   | name | string | 名前 |
   | dept | string | front（フロント）または hk（管理課） |
   | admin | boolean | true |
   | active | boolean | true |
5. アプリで社員番号とパスワードでログイン → ⚙ 設定 → 部屋番号を登録 → 他の社員を登録

## 3. 運用
- ログイン：社員番号＋パスワード（各自のスマホ）。ログインした本人の名前で操作が記録される
- 社員の登録・編集・利用停止：管理者が ⚙ 設定 から行う。利用停止にするとその時点からアクセス不可
- パスワード変更：本人が ⚙ 設定 → パスワード変更
- パスワードを忘れた場合：管理者が Firebase コンソールの Authentication でパスワードを再設定
- 管理者は画面上部の「表示切替」で、フロント／管理課の画面を切り替えられる
- ログアウトすると、端末に残っているデータも消去される

## 画面
- トップ（共通）：今日の状況、未完了の特別対応（日付・持ち越し／明日分の表示つき）、各画面へのボタン
- フロント：清掃日程表（赤＝要清掃／緑＝清掃なし・タオル補充／灰＝未入力）、特別対応指示表
  - 日程表は 23:59 まで「今日」を初期表示。翌日分は画面上部の「明日」に切り替えて入力
  - 赤のペンは「連泊清掃」と「C/O」の2種類。C/Oはフロント画面だけの印で、管理課のボードには同じ赤で表示（履歴画面では表示）
  - 「前日から下書き」：前日C/O→灰、前日連泊清掃→緑、緑が3日続いた→赤、それ以外の緑→緑（入力済みの部屋は変更しない。サーバーの最新データで判定するため、通信できる状態でのみ実行可）
  - まとめ塗り：反映前に、対象の室数・未登録の番号・読み取れない指定を確認表示
  - 管理課が完了済みの部屋も、確認のうえ変更できる（完了していた記録は操作履歴に残る）
- 管理課：清掃ボード（赤・緑をタップで白＝完了、白をタップで取消）、特別対応完了報告（実際に対応した人＋一言。完了報告は取り消し不可。未対応だった場合はフロントが特別対応を新たに登録する）
- 履歴（共通）：過去30日。部屋の行をタップ（または部屋番号を入力）すると、その日の操作履歴（誰が・いつ・何から何に変えたか）を表示。特別対応は「操作履歴を見る」で表示
- 画面上部の同期表示：同期済み（時刻）／同期中／接続中…／オフライン・未送信／同期エラー（タップで内容）
- 日付・時刻はすべて日本時間で判定（端末の時刻設定に依存しない）

## 部屋番号の書き方（設定画面）
```
2: 201-230
3: 301-330, 335
10: 1001-1025
```

## データ構造
- users/{uid} … empNo / name / dept（front・hk）/ admin / active / createdAt / createdBy / updatedAt / updatedBy
- config/hotel … floors（階 → 部屋番号の配列）/ updatedAt / updatedBy
- days/{日付}/floors/{階} … rooms.{部屋番号} に s（red/green）/ co（C/Oならtrue）/ setBy / setAt / doneBy / doneAt、expireAt
- specials/{自動ID} … room / floor / date（対応日）/ text / createdBy / createdAt / done / handler（実際に対応した人）/ note / reportedBy（報告した人）/ doneAt / doneDate / expireAt
- logs/{自動ID} … 操作履歴。uid / name / at（サーバー時刻）/ type / expireAt と、
  - 部屋の操作：date / floor / rooms（部屋番号の配列）/ changes.{部屋番号}.b（変更前）.a（変更後）
  - 特別対応：sid / room / date / b / a
  - 設定・社員：target / b / a
  - 追加のみ可能。変更・削除はルールで禁止
